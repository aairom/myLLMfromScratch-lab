Abstract

This sub-task assembles the parts of the previous three into a decoder-only transformer, the architecture family of GPT (Radford et al., 2018, 2019). It explains the residual stream, the pre-norm block, the tied output head and weight initialisation, defines the training loss (cross-entropy), and describes how text is generated one token at a time with temperature, top-k and nucleus sampling. The default model has 103,360 parameters.

The model as a function

A GPT with N layers maps a sequence of token ids x1,…,xT to a matrix of scores (logits) zt∈ℝV, one row per position, where zt scores every vocabulary entry as the possible next token:

Pθ(xt+1∣x≤t)=softmax(zt).

The computation is a fixed pipeline:

𝐡t(0)&=Ext+𝐩t𝐡(ℓ)&=Blockℓ(𝐡(ℓ−1)),ℓ=1,…,Nzt&=LNf(𝐡t(N))E⊤.

The last line is the tied output head: the logit of token j is the dot product of the final hidden state with the embedding of j.

The residual stream and the pre-norm block

Each block updates a running vector, the residual stream, by adding corrections to it. With the pre-norm layout used here (GPT-2, Radford et al., 2019):

𝐮=𝐡+MHA(LN1(𝐡)),𝐡′=𝐮+FFN(LN2(𝐮)).

The identity path (𝐡→𝐮→𝐡′) is the crucial feature, introduced as residual connections by He et al. (2016) for image networks. It gives gradients a direct route from the loss to every layer, so depth does not make optimisation exponentially harder. Elhage et al. (2021) describe the same structure as a communication channel: attention heads and feed-forward layers read from and write to a shared stream.

Measured: blocks write small corrections

At initialisation the stream entering the first block has a mean vector norm of about 5.66, almost entirely the positional signal (see the embedding document). The attention and feed-forward outputs added by each block have mean norms of only about 0.10 to 0.11. Each sub-layer therefore starts as a gentle perturbation of the stream, and the loss at initialisation is close to the uniform-guess value: about 3.95 on a batch of random token ids, against ln(51)=3.932.

Why initialise residual outputs smaller

The last projection in each residual branch (the attention output projection and the second feed-forward matrix) is initialised with standard deviation 0.02/2N, which is 0.010 for N=2. A stream receives 2N additions; if each had variance σ2, their sum would have variance 2Nσ2. Scaling by 1/2N keeps the stream's growth independent of depth, as in GPT-2. All other linear layers use standard deviation 0.02.

Two features are worth noting. First, the feed-forward layers hold about two thirds of all parameters. Second, because the output head is tied, a vocabulary of V entries adds V·d parameters once, not twice. With a larger vocabulary (BPE) the embedding share grows; with a tiny character vocabulary it is small.

The training objective

The model is trained to maximise the likelihood of the training text, equivalently to minimise the cross-entropy between the data distribution and the model's predictions. For Ntok prediction targets:

ℒ(θ)=−1Ntok∑i=1Ntoklogsoftmax(zi)yi.

Computing logsoftmax directly overflows for large logits, so the implementation uses the identity

logsoftmax(z)y=zy−log∑jezj=zy−logsumexp(z),

with logsumexp evaluated in a numerically stable way (it subtracts the maximum internally). The result equals PyTorch's reference cross-entropy to within a small tolerance, which the test suite verifies.

Reference values.

  • A model that guesses uniformly has loss lnV=3.932 nats per token.
  • A model that knows only the frequencies of the characters reaches the unigram entropy, about 3.031 nats on the training split.
  • Perplexity is eℒ, the effective number of equally likely choices the model hesitates between. A loss of 3.086 corresponds to a perplexity of 21.9 for the reference run, compared with 51 for a uniform guess.

Every position predicts its own next token in a single forward pass, so a window of T tokens provides T training examples at once. This is teacher forcing: the model always sees the true previous tokens while learning, and the causal mask guarantees that it cannot peek at the answer.

Generation

At inference the model is run autoregressively: predict a distribution for the next token, choose one, append it, and repeat.

  1. Crop the sequence to the last L tokens, the context window, because positions beyond it are not defined.
  2. Run the model and keep the logits of the last position only.
  3. Convert them to a probability distribution, with optional adjustments below.
  4. Sample a token from that distribution and append it.

Temperature

Dividing the logits by a temperature τ>0 before the softmax changes how peaked the distribution is:

pj(τ)=ezj/τ∑kezk/τ.

For τ<1 the distribution sharpens toward the largest logit; for τ>1 it flattens; τ→0 is greedy decoding, the arg-max, which is how temperature = 0 is implemented. Worked example with logits (2.0,1.0,0.1):

Setting Probabilities
τ=1 0.659, 0.242, 0.099
τ=0.5 0.864, 0.117, 0.019
τ=2 0.502, 0.304, 0.194
top-k with k=2 0.731, 0.269, 0
top-p with p=0.8 0.731, 0.269, 0

Top-k and nucleus (top-p) sampling

Pure sampling occasionally picks a very unlikely token, after which the continuation can derail. Top-k keeps only the k highest logits (Fan et al., 2018). Nucleus sampling (Holtzman et al., 2020) keeps the smallest set of tokens whose cumulative probability reaches p, so the number of candidates adapts to how confident the model is. After either filter the remaining probabilities are renormalised. The implementation always retains at least one token.

Greedy versus sampled text

Greedy decoding is deterministic and tends to repeat itself; sampling is varied but can be incoherent. The choice is a quality-diversity trade-off, not a correctness question, and the interface lets the learner vary all three parameters.

What a small model can and cannot do

The reference run reaches a validation loss of 3.086 after 300 steps, and the unigram entropy of the validation text is 3.085. The model has therefore learned character frequencies, not yet context, and its samples look like random letters with the right proportions.

Training longer helps: 2.134 validation loss after 1,500 steps, which is clearly below the unigram level, so the model now uses context. Even then, a corpus of 4,876 characters is far too small for fluent text, and long training shows overfitting (see the training explanation). Text sampled after 3,000 steps is word-like but nonsensical, which is what one expects from a model that has memorised local spelling patterns of a tiny corpus.

Limitations

  1. Scale. 103,360 parameters is about three orders of magnitude fewer than GPT-2 small (124 million), and a corpus of 4,876 characters is many orders of magnitude smaller than the web-scale text such models see. Emergent abilities reported for large models (Wei et al., 2022) are out of reach by design.
  2. No key-value cache. Generation recomputes the whole window for every new token, costing O(T2) attention per step. Production systems cache keys and values; this implementation favours clarity.
  3. Context length. Text longer than the window is cropped from the left, so the model forgets the beginning.
  4. Sampling on CPU. The random draw is made on the CPU so a seeded CPU generator gives identical results on any device, including Apple's MPS.
