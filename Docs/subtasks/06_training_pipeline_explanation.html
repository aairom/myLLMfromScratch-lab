Abstract

Training turns a randomly initialised network into a language model by repeatedly nudging its parameters to lower the next-token loss. This document explains the whole loop: how text becomes windowed batches, how gradients are obtained by backpropagation, how Adam and SGD turn gradients into updates, why the learning rate follows a warm-up and cosine schedule, and why gradients are clipped. It then reads the reference run honestly: in 300 steps the loss falls from 3.967 to 3.037, but the validation loss of 3.086 shows the model has learned letter frequencies and not yet context.

Data: from a token stream to batches

Windows and the shift-by-one target

After tokenization the corpus is one long sequence of ids d1,d2,…,dN. A training example is a window of T+1 consecutive ids. The model sees the first T and is asked to predict, at every position, the id that follows:

x=(ds,…,ds+T−1),y=(ds+1,…,ds+T).

Because the causal mask hides the future, one window supplies T training examples in a single forward pass. A batch stacks B windows whose start positions s are drawn uniformly at random, so one step trains on B·T tokens. The reference run uses B=16 and T=32, which is 512 tokens per step.

Train and validation split

The token stream is cut into a training part and a validation part that the optimiser never sees. The cut is contiguous (the last 10 %), not shuffled: a shuffled split would put neighbouring characters on both sides of the boundary and let the model "see" its validation text through overlapping context. For the bundled corpus the split is 4,389 training and 487 validation tokens.

How much data is that?

The reference run processes 153,600 tokens in total, which is about 35.0 passes over the training split. With so few distinct tokens the model sees every training character many times; this is the root of the overfitting shown below.

Backpropagation

With parameters θ and loss ℒ(θ), learning needs the gradient g=∇θℒ. The loss is a composition of differentiable operations, so the chain rule gives the gradient layer by layer, from the output backwards. For a composition ℒ=fn∘⋯∘f1 with intermediate values ak=fk(ak−1),

∂ℒ∂ak−1=(∂ak∂ak−1)⊤∂ℒ∂ak.

Reverse-mode automatic differentiation (Rumelhart, Hinton and Williams, 1986) stores the forward activations and applies this recurrence once, so the cost of the full gradient is a small constant multiple of one forward pass, however many parameters there are. In PyTorch loss.backward() performs it and fills p.grad for every parameter. Residual connections help here: the identity path adds a term 1 to each layer's Jacobian, so the gradient reaching early layers does not shrink geometrically with depth.

Optimisers

An optimiser maps the gradient to an update. All of them below are written by hand in this project, with the same interface as torch.optim, and tested step by step against PyTorch's implementations.

Plain gradient descent and momentum

The simplest rule moves against the gradient, θ←θ−ηg, with learning rate η. Momentum (Polyak, 1964) accumulates a velocity so consistent directions speed up and oscillations cancel:

bt=μbt−1+gt,θt=θt−1−ηbt.

Adam

Adam (Kingma and Ba, 2015) keeps two running averages per parameter, the first moment (mean) and the second moment (uncentred variance) of the gradient:

mt=β1mt−1+(1−β1)gt,vt=β2vt−1+(1−β2)gt2.

Both start at zero, so early estimates are biased towards zero; the correction divides by 1−βt:

m^t=mt1−β1t,v^t=vt1−β2t,θt=θt−1−ηm^tv^t+ε.

The division by v^t gives every parameter its own effective step size. A useful consequence: at the very first step m^1=g1 and v^1=|g1|, so the update has size about η regardless of how large or small the gradient is. Measured with η=0.01, a gradient of 123 and a gradient of 0.001 both moved the parameter by about 0.01. Adam is thus largely insensitive to the gradient's scale, which is one reason it is robust for transformers; the price is that η must still be chosen with care.

Weight decay: L2 versus AdamW

Weight decay shrinks weights to discourage large values. In Adam with L2 regularisation the penalty λθ is added to the gradient, so it passes through the adaptive scaling and decays parameters unevenly. AdamW (Loshchilov and Hutter, 2019) decouples the decay: weights are first shrunk directly, θ←(1−ηλ)θ, and only then updated by the Adam rule. The reference run uses AdamW with λ=0.01.

A simplification to be aware of

The implementation applies the same weight decay to every parameter, including biases, LayerNorm scales and embeddings. Large-scale training usually excludes these. At this scale the difference is small.

Learning-rate schedule

A fixed learning rate is rarely best. At the start the weights are random and Adam's moment estimates are poor, so large steps can derail training; near the end smaller steps let the model settle. The schedule used here (two options exist: warmup_cosine and constant) has two phases (Loshchilov and Hutter, 2017; Goyal et al., 2017):

ηt={ηmaxt+1twt<tw(linear warm-up)[2ex]ηmin+12(ηmax−ηmin)(1+cosπt−twTtotal−tw)t≥tw(cosine decay)

with ηmin=rηmax (here r=0.1). For the reference run, ηmax=0.003, warm-up tw=20 steps, and the rate ends at 0.0003. Computed values: step 0 gives 0.00015, step 19 reaches 0.003, step 160 gives 0.00165 and step 299 gives 0.0003.

Gradient clipping

Occasionally a batch produces a very large gradient (a loss spike), and one huge step can undo much progress. Global-norm clipping (Pascanu et al., 2013) rescales the whole gradient vector if its L2 norm exceeds a threshold c:

g←g·min(1,c‖g‖2).

The direction is preserved; only the length is capped. The reported gradient norm is the value before clipping, which makes it a useful health signal. In the reference run it starts at 1.383, peaks at about 1.44 and ends at 0.227, with a clipping threshold of 1. The norm exceeded the threshold in only 14 of the 300 steps, all of them among the first 14, so clipping acted only at the very start (the peak was at step 3); afterwards gradients were left untouched.

Reading the loss curves

The reference run (seed 42, AdamW, learning rate 0.003, batch 16, window 32) shows three things.

  1. Fast initial drop. The training loss falls from 3.967 to about 3.16 by step 20 and to about 3.06 by step 30. This is the model learning the unigram distribution: which characters are common.
  2. A plateau at the unigram floor. The validation loss sits between 3.090 and 3.100 for the rest of the run, ending at 3.086. The entropy of the character frequencies themselves is 3.031 nats on the training text and 3.085 on the validation text. A model that has learned only letter frequencies cannot do better than this, so after 300 steps the model has not yet learned to use context. Its perplexity is 21.9 on validation, against 51 for a uniform guess.
  3. Cheap to run. The run takes 3.6 s on mps (about 42,000 tokens per second); the same seed gives identical losses on the CPU.

Training for longer

Longer runs on the same corpus show what happens once the model starts using context:

Run Final training loss Validation loss at step 750 Validation at step 1,000 Final validation loss
1,500 steps, window 32 1.956 2.780 2.346 2.134
3,000 steps, window 64 1.309 2.643 2.373 2.182 (best 2.022 at step 1850)

Both longer runs stay on the unigram plateau (validation about 3.10 up to step 500 in the 3,000-step run) and then drop sharply between steps 500 and 750, well below the unigram entropy of 3.085. That sudden fall is the point at which the model starts to use context; the plateau is a stage the reference run never leaves within its 300 steps. The 3,000-step run is the classic overfitting picture: training loss 1.309 against a best validation loss of 2.022 reached at step 1850, then a worse validation loss at the end (2.182). The gap between the curves means the model is memorising the 4,389 training tokens rather than generalising. The usual remedies are more data, dropout, weight decay, a smaller model, and early stopping at the best validation step.

In-sample entropies are optimistic

Bigram and trigram conditional entropies of the training text (2.18 and 1.31 nats) are measured on the same text they describe, so they flatter a model that memorises. Only the validation loss measures generalisation.

Evaluation

Every 25 steps by default (plus the first and the last step) the validation loss is estimated by averaging over 10 fixed random batches with dropout switched off. The batch generator is seeded with a constant, so two evaluations of identical weights return the same number and differences reflect the model rather than the sample.

Checkpoints

A checkpoint stores the model weights, architecture config, tokenizer vocabulary (the ids mean nothing without it), the training config, the loss history and the optimiser state, so a run can be reproduced or inspected later. Files are named with a timestamp and are never overwritten.

Limitations

  1. Tiny scale. The conclusions about the plateau and overfitting are specific to this corpus and model size; scaling laws (Kaplan et al., 2020) describe how loss improves with parameters, data and compute at much larger scales.
  2. No data pipeline sophistication. Windows are sampled with replacement and may overlap; there is no epoch shuffling, packing or mixed precision.
  3. Single seed. The numbers come from one seed. Run-to-run variation exists and is not quantified here.
  4. Validation doubles as selection set. There is no separate test split, so picking the best validation step would slightly overstate performance.
